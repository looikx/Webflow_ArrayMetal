What this structure buys you

  1. Nine families, twenty systems, four hundred product pages, a few thousand item codes. Øglænd publishes 1,215 product pages and 11,244 codes; Atkore publishes 537 product pages. You land in the same band while 98% of the generated catalogue stays in the costing system.
  2. Specs are never typed twice. Dimensions, item codes and weights render from the costing database. If a product type ships in costing, its card appears on the system page automatically.
  3. Marketing owns the words, engineering owns the numbers. There is no field anywhere in the CMS where someone can type a width — so the copy can never contradict the table beneath it.
  4. The long tail stays reachable. Any of the 574,609 combinations resolves through the configurator and can be added to an enquiry, even though only a few thousand are listed and indexed.
  5. No prices anywhere. Neither Øglænd nor Atkore shows one. The enquiry list is the conversion point.

Data provenance. Systems, heights, widths, thicknesses, lengths, product types and SKU counts are read from the live costing database (574,609 items, queried 2026-08-10). SWL values, NEMA classes, loading depths, standards and safety factors are from Array Metal’s published load-ratings page. Item codes follow the real part-number grammar. Unit weights, ART numbers and the ETIM code shown in the mockups are illustrative placeholders — real weights come from the engine, and the ETIM classes need to be assigned per product type.
